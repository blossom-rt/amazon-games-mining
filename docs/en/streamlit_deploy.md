# Streamlit Community Cloud Deployment

## Goal

Deploy `src/dashboard_app.py` to Streamlit Community Cloud to get a stable domain:

```text
https://<app-name>.streamlit.app
```

GitHub only stores the code; Cloud runs the Python service. GitHub Pages can only host static HTML and cannot run Streamlit.

## Files That Must Exist Before Deployment

| File | Role |
| --- | --- |
| `src/dashboard_app.py` | Application entry point |
| `requirements.txt` | Dependencies installed by Cloud by default; already includes `streamlit`, `plotly`, `pandas` |
| `results/tables/cluster_outcomes.json` | Cluster view |
| `results/tables/classify_time.json` | Time view |
| `results/tables/network_compare.json` | Network view |
| `results/tables/classify_summary.json` | Overview and model metrics |

These JSON files under `results/tables` must be committed to GitHub. The raw gzip and parquet files do not need to be committed.

The dashboard dependencies can also be installed separately for local use:

```powershell
pip install -r requirements-dashboard.txt
```

However, Community Cloud reads `requirements.txt` at the repository root by default, so that root file also keeps `streamlit` and `plotly`.

## Pushing the Code

From the repository root, review the changes and push:

```powershell
git status --short
git add requirements.txt src/dashboard_app.py results/tables docs/streamlit_deploy.md
git commit -m "docs: add Streamlit Cloud deployment guide"
# main is protected: push to a feature branch and open a PR; deployment triggers after the merge
git switch -c docs/streamlit-deploy
git push -u origin docs/streamlit-deploy
```

Before committing, confirm the staging area contains no `data/raw`, `data/processed`, or `.parquet` files.

## Creating the App

1. Open <https://share.streamlit.io> and sign in with GitHub.
2. Select **Create app**.
3. Fill in:

| Field | Value |
| --- | --- |
| Repository | `blossom-rt/amazon-games-mining` |
| Branch | `main` |
| Main file path | `src/dashboard_app.py` |

4. Open **Advanced settings** and select **3.11** for Python.
5. Click **Deploy** and wait for the build log to finish.

After a successful build the address looks like `https://<app-name>.streamlit.app`. Current app: [Open the Streamlit app](https://amazon-games-mining-dashboard.streamlit.app/); the actual address is whatever App URL the Cloud page shows.

## Redeploying After a Data Update

The dashboard reads JSON from the repository. After updating results:

```powershell
python src/run_all.py --extras
git add results/tables/*.json
git commit -m "chore: refresh dashboard data"
git switch -c chore/dashboard-data
git push -u origin chore/dashboard-data
# open a PR into main; Cloud deploys automatically after the merge
```

Cloud redeploys automatically when it detects an update on the `main` branch. If the page still shows old data, choose **Reboot app** from the menu in the app's top-right corner.

## Runtime Limits

- Free apps sleep after a period of inactivity, and reopening them requires waiting for the wake-up.
- The free tier has memory and runtime limits and is not suitable for sustained high concurrency.
- Apps are public by default; the pages contain only aggregate results, with no personal information such as reviewer names or reviewerID.
- The current `dashboard_app.py` does not read parquet; it reads only four JSON files, so startup is fast and memory use is small.

## Common Issues

**`ModuleNotFoundError: streamlit` during the build**

The root `requirements.txt` is missing `streamlit`, or the app is connected to the wrong branch. Confirm the file contains:

```text
streamlit==1.67.0
plotly==7.1.0
```

**`ModuleNotFoundError: pandas` during the build**

The root `requirements.txt` is missing `pandas`. This project pins `pandas==3.1.1`.

**`FileNotFoundError` on the page**

The four JSON files were not committed to GitHub, or the branch is not the expected `main`. Check with:

```powershell
git ls-files results/tables/cluster_outcomes.json results/tables/classify_time.json results/tables/network_compare.json results/tables/classify_summary.json
```

**Build timeout**

The root `requirements.txt` contains heavy research dependencies such as shap, lime, and jupyterlab. If the Cloud build times out, create a branch used only for deployment and keep only the following in its root `requirements.txt`:

```text
pandas==3.1.1
numpy==2.4.6
streamlit==1.67.0
plotly==7.1.0
```

Point the app at that branch and carry the data JSON files over with it.

**The app keeps spinning**

First request `https://<app-name>.streamlit.app/_stcore/health`. A response of `ok` means the service has started; refresh the browser or reboot. Corporate proxies may block WebSocket connections.

## Alternatives

- **Static version**: `results/dashboard.html` is generated by `src/build_static_dashboard.py`; all four views and both linked filters run in the frontend. Once merged into GitHub it can be served through raw.githack or GitHub Pages.
