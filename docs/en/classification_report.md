# Review Sentiment Classification Report (P4)

This report covers the project's classification acceptance requirements: a baseline plus at least 3 models (including an ensemble), stratified 5-fold, mean ± standard deviation, statistical testing, ≥3 metrics, confusion matrices and ROC/PR curves, error-sample dissection, global importance, and SHAP local explanations. All numbers are generated by `python src/classify.py`.

## Samples and Labels

- Samples: game-product reviews with `in_scope=True` in `features.parquet`, 1,456,092 in total, with a positive-class rate of 74.75%.
- Labels: `label = 1` if and only if `overall >= 4.0`; the negative class is 1–3 stars.
- Folds: read directly from the `fold` column of `folds.parquet`; the 5 folds come from `StratifiedGroupKFold(groups=asin)`, so reviews of the same product never span folds.
- Out-of-scope reviews (`fold = -1`) do not enter training, validation, or metric computation.

## Leakage Prevention

Within each training fold the following objects are fitted in order; the validation fold is only `transform`ed:

1. Median imputation and missing-indicator columns for numeric features (`SimpleImputer`).
2. Standardization of numeric features (`StandardScaler`).
3. One-hot encoding of categorical features (`OneHotEncoder`, rare categories merged).
4. IDF weights of the text TF-IDF (`TfidfTransformer`); the vocabulary comes from a fixed-dimension `HashingVectorizer` and never uses validation-fold text.
5. The `TruncatedSVD` used by the tree models is fitted only on 100,000 rows from the training fold.

Outside the folds, text vectorization performs only unsupervised hashing and never reads labels; IDF, SVD, imputation, encoding, and standardization never touch the validation fold.

## Text and Features

- Text: `reviewText + " " + summary`, truncated to 3,000 characters.
- Vectorization: `HashingVectorizer(n_features=262144, alternate_sign=False, norm=None)`; all 5 folds share the same hash space, and IDF is refitted per fold.
- Linear-model input: 34 numeric features + one-hot encoding of 2 categorical features + 262,144-dimensional TF-IDF, concatenated as a sparse matrix.
- Tree-model input: 34 numeric features + 20 SVD dimensions, avoiding building trees directly on a 260k-dimensional sparse matrix.
- Numeric features include the time-window features `reviews_prev_30d_same_asin` and `days_since_prev_review_same_asin`; definitions are in `docs/feature_dictionary.md`.

## Models

| Model | Key settings |
|---|---|
| Dummy | Predicts the training-fold prior; serves as the baseline |
| Logistic regression (SGD) | `loss=log_loss`, `alpha=1e-5`, `max_iter=8`, `class_weight=balanced` |
| Linear SVM (SGD) | `loss=hinge`, `alpha=1e-5`, `max_iter=15`, `class_weight=balanced` |
| HistGradientBoosting | 120 iterations, learning rate 0.08, 31 leaves, early stopping, balanced sample weights |
| Random forest | 60 trees, max depth 18, minimum 40 samples per leaf, `balanced_subsample` |

Class imbalance is handled through `class_weight`/sample weights; no resampling is performed, to avoid changing the validation distribution.

## Results

Mean ± standard deviation over 5 folds, OOF predictions:

| Model | Accuracy | Macro F1 | PR-AUC | ROC-AUC |
|---|---|---|---|---|
| Dummy | 0.7475 ± 0.0000 | 0.4277 ± 0.0000 | 0.7475 ± 0.0000 | 0.5000 ± 0.0000 |
| Logistic regression (SGD) | 0.8849 ± 0.0100 | 0.8583 ± 0.0097 | 0.9838 ± 0.0011 | 0.9551 ± 0.0023 |
| Linear SVM (SGD) | **0.8894 ± 0.0064** | **0.8635 ± 0.0065** | 0.9837 ± 0.0016 | **0.9569 ± 0.0024** |
| HistGradientBoosting | 0.8164 ± 0.0028 | 0.7849 ± 0.0027 | 0.9701 ± 0.0005 | 0.9160 ± 0.0016 |
| Random forest | 0.8066 ± 0.0033 | 0.7747 ± 0.0031 | 0.9673 ± 0.0005 | 0.9086 ± 0.0016 |

The best model is the linear SVM (SGD), with a macro F1 of 0.8635; logistic regression is very close to it, indicating that the main signal comes from TF-IDF surface tokens. Both tree models are clearly lower, because the 20-dimensional SVD compresses the text and tree models are poor at 260k-dimensional sparse linear boundaries.

Statistical test: a Wilcoxon signed-rank test on the 5-fold macro F1 of the best model against Dummy gives `W = 0.0`, `p = 0.0625`; with a sample size of 5 folds this is the smallest possible p-value and does not reach the 0.05 significance level, so the main text states "consistent in direction but with an insufficient sample size".

## Error Sample Dissection

`results/tables/classify_errors.csv` takes the 5 false positives with the highest OOF scores and the 5 false negatives with the lowest scores from the best model, keeping only one review per product. The shared patterns are as follows.

False positives (truly negative, predicted positive):

1. `B00IWMAREW` (Xbox 360 hard drive): the review says "can't play original Xbox games, but otherwise it's great"; the negative fact is outweighed by `good`.
2. `B01BHFI4XG` (ASUS VR console): a long review describing a failed installation, a blue screen, and a final return, but it opens with `fun`, so surface positive words win out.
3. `B000ZKA0J6` (game): a lengthy discussion of the game's strengths, with criticism only at the end, so the overall surface leans positive.
4. `B006UIS53K` (Kinect hardware): the review calls the product a "paperweight" and notes "no manual", but words such as `Windows`, `games`, and `useful` share the same distribution as game reviews.
5. `B005OTUJXA` (Games category): the short review "not worth anything over 350$"; the negation structure is not captured by the linear model.

False negatives (truly positive, predicted negative):

1. `B0009VXAM0` (PS3): a long comparison of three consoles containing negative phrases such as `lower resolution` and `tighter budget`, but the overall assessment is positive.
2. `B000I20TBU`: the body is only `good`, four characters; there is too little text evidence, so category/product features pull the model toward negative.
3. `B000EGELP0` (Brain Age): the review first says `hardly groundbreaking` and `monotonous`, then `strangely addictive`; the concessive sentence is dominated by its first half.
4. `B000CFMQPK` (Office Products / Games): `easily installed and nice...` is positive, but the product category differs greatly from game products.
5. `B000SL4ANE` (Chessmaster): many paraphrased quotations of `poor reviews` and `doesn't compare`, while the actual conclusion is a recommendation.

These errors cluster into four types: negation and contrast, short text, rating–text inconsistency, and hardware/accessory products that still slip through scope determination. The last type matches the 226 strong hardware-word candidates recorded in `docs/scope_definition.md`.

## Global Importance and SHAP

- The top permutation importances are almost all SVD dimensions (`svd_02`, `svd_13`, `svd_14`, and so on), followed by `summary_len`, `review_word_count`, `vote_count`, and `has_vote`; the time-window feature `reviews_prev_30d_same_asin` contributes a little but far less than text.
- The three SHAP samples cover a false positive, a false negative, and a true positive: the false positive is pushed up by the positive contribution of `svd_02`; the false negative is pulled down by `svd_13` and `summary_len`; the true positive is affected by both `svd_02` and `summary_len`. Full values are in `results/tables/classify_shap.json`.

## Limitations

- The linear SVM decision score is not a calibrated probability; PR/ROC are unaffected, but business thresholds require additional calibration.
- Text is truncated to 3,000 characters, so the latter part of very long reviews never enters the model.
- Negation, sarcasm, and rating–text conflicts remain the main error sources; no syntax or pretrained language model is used.
- The 226 strong hardware-word candidates retained by scope determination still enter the classification sample, and hardware products already appear among the error samples.
- The Wilcoxon p-value floor with 5 folds is 0.0625, so 0.05 significance cannot be claimed on this data; conclusions are stated in terms of direction and effect size.
